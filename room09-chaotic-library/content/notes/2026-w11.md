Ça s'améliore, mais on peut pas encore les laisser même 5min dans la même pièce sans surveillance.

À côté, j'ai eu quelques galères pour highlight les shortcodes de {{ al(k="Tera") }} dans le `markdown-mode` d'Emacs, pour l'instant, j'ai pas trouvé la solution pour highlight individuellement les paramètres. Il faudrait que j'arrive à faire un subregex qui vient cibler individuellement chaque couple paramètre/valeur dans mon regex principal, je sais que c'est possible, mais je voulais pas perdre plus de temps que ça dessus pour le moment.

Pour l'instant ça ressemble à ça :
```lisp
(defun v3rmine/markdown-add-tera-shortcode-keyword ()
  "Enable fontifying Tera shortcodes."
  (let ((shortcode-regexp
         (rx
          (group-n 1 "{" (or "{" "%") (* space))              ; opening {{ or {%
          (group-n 2 (* (or alpha "_")))                      ; shortcode name
          (optional
           (* space)
           (group-n 3 "(" (* space))                          ; opening (
           (group-n 100 (*? any))
           ;; (*
           ;;  (group-n 4 (1+ (or alpha "_")))                   ; parameter name
           ;;  (?? (group-n 5 (* space) "=" (* space)))          ; delimiter
           ;;  (?? (or                                           ; ignore
           ;;          (group-n 6 (or "true" "false" (1+ num)))  ; constant or num
           ;;          (group-n 7 "\"" (*? any) "\"")            ; string
           ;;          (group-n 8 "'" (*? any) "'")))            ; string
           ;;  (? (group-n 9 (* space) "," (* space)))           ; ,
           ;;  )
           (group-n 10 (* space) ")")                         ; closing )
           )
          (group-n 11 (* space) (or "}" "%") "}"))))          ; closing }}, %}
    ;; https://stackoverflow.com/questions/13216058/emacs-syntax-highlighting-of-optional-parts
    (font-lock-add-keywords nil `((,shortcode-regexp . 
                                    ((1 'markdown-markup-face)
                                     (2 'font-lock-type-face)
                                     (3 'markdown-markup-face nil t)
                                     (100 'font-lock-string-face nil t)
                                     ;; (4 'font-lock-variable-name-face nil t)
                                     ;; (5 'markdown-markup-face nil t)
                                     ;; (6 'font-lock-type-face nil t)
                                     ;; (7 'font-lock-string-face nil t)
                                     ;; (8 'font-lock-string-face nil t)
                                     ;; (9 'markdown-markup-face nil t)
                                     (10 'markdown-markup-face nil t)
                                     (11 'markdown-markup-face)
                                    ))))))
```

# 🌐 Articles
- [How Kernel Anti-Cheats Work: A Deep Dive into Modern Game Protection](https://s4dbrd.github.io/posts/how-kernel-anti-cheats-work/) Un deep-dive (bien deep {{ customoji(name="CatLoading") }}) qui explore le fonctionnement de BattleEye, EasyAntiCheat, Vanguard et FACEIT AC. C'est intéressant de voir le jeu de chat et de la souris qui va de plus en plus loin dans la surveillance de la machine (pour tous les joueurs) pour que ce soit toujours plus difficile de tricher (mais à quel prix du coup).
- [LEGO Machine Plays Tic-Tac-Toe Without Electronics](https://hackaday.com/2026/03/16/lego-machine-plays-tic-tac-toe-without-electronics/) Une machine entièrement mécanique en Lego qui joue au Morpion. Un petit bijou d'ingénierie, c'est beau ! {{ customoji(name="Amazed") }}
- [La Suite numérique de l’État : critique des critiques](https://framablog.org/2026/03/19/la-suite-numerique-de-letat-critique-des-critiques/) Un super article de Framasoft qui parle de l'histoire du libre et de l'état, combien ça coûte, les réussites et les échecs. Et alerte encore sur le torpillage possible par les gros éditeurs propriétaires.
- [Naturalest sort](https://leanrada.com/notes/naturalest-sort/) Un article qui parle non pas de comment on pourrait utiliser des LLM pour trier des mots avec un ordre naturel. Mais comment on pourrait utiliser les ["Word Embeddings"](https://en.wikipedia.org/wiki/Word_embedding) et leurs propriétés mathématiques pour faire des calculs sur différents axes et trier les mots avec un ordre naturel. Bon spoiler, c'est pas simple parce qu'il existe plein de manières de trier des mots.
